# JUE-0009: word data clean-up and expansion

Every game draws from the definition files `public/definitions/<locale>/<letter>_definitions.json`
(26 files per locale). Today:
- **es:** 9,010 words;
- **en:** 45,984 words.

The entry shape is `word → {definitions: [{number, type, type_extra?, definition, definition_extra?}]}`.

The data was built with the crawlers in `scripts/crawlers/`:
- RAE for es: 10 requests/min, 100/day, exits with code 2 when the quota runs out;
- dictionaryapi.dev and Merriam-Webster (needs `MW_API_KEY`) for en.

It also went through the word scripts in `scripts/words/`: transform, merge, check, clean,
sort-by-frequency and from-book. See `ops/docs/commands.md`.

Owner decision (2026-11-03): improve every word with its definitions, remove junk, and expand the
lists.

## Pending (one phase per PR, in order; each launch does the first unchecked phase)
- Phase 1 (audit and clean) shipped in PR #60; Phase 2 (word model, IndexedDB v2, query API, every
  game moved, pools unchanged) shipped in PR #64. The model, level formula and query API are in
  `ops/docs/game-conventions.md`. Carry-over for later phases (all FLAG in `words:audit`, none blocks
  a game):
  - es: 4,419 senses carry `type_extra: "sin verificar"` (English RAE labels mapped to generic heads),
    which is the Phase 3 re-crawl list; 1,155 single-word senses (D3b, RAE synonyms/redirects).
  - es foreign-word candidates (W9, 1,732), accent-only pairs (W12, 96, e.g. `vehiculo`), cross-level
    duplicates (W13); 55 es senses with leftover `( H 2 O)`-style fragments.
  - en `LETTERS_WITHOUT_DEFINITIONS` j/k/l/z looks stale; es definitionMaster advanced K/W has no pool
    (pre-existing hang); duplicate option texts in definitionMaster.
  - Run `yarn words:audit --fix` then `yarn words:build` after any crawl, book import or list edit.
  - **Before Phases 3–5 change any served list:** IndexedDB has no data-version stamp. The populated
    check only proves the level's last position exists, so a level that shrinks or loses words is not
    refreshed for existing users. Add a per-level stamp (chunk version + row count/hash) or clear the
    locale stores on a `WORDS_DATA_VERSION` bump.
  - Phase 2 left on purpose: unranked words keep their source-list level (JUE-0017/0018 retire it);
    `LEVEL_BANDS` 3000/10000 is provisional (JUE-0017); `source` is `rae` or `null` (Phases 4–5 fill
    wiktionary/mw/dictionaryapi); senses are not on the record (`getDefinition(s)` reads them).
  - Residual from Phase 2 QA: the first full es populate is ~2.5× v1 time and ~1.8× v1 storage;
    `DBUpgradeBlockedError` is logged but the page stays loading; `getFullWordSet` populating another
    level wipes the per-game queues; the prefetch length windows differ from the per-level game windows
    (e.g. wordFinder beginner); a game can start with 0 words when populate fails (all pre-existing
    except the populate cost).
- [ ] **Phase 3: definition quality (es).**
  - For words with weak definitions, re-crawl RAE: those with only a "forma de" reference, a missing
    type, or more than 6 senses that overwhelm the definition games.
  - Respect the quota: at most 100 per run. Keep a progress file so later runs continue where this
    one stopped, and make the crawler resume.
  - Add a `primary` sense flag, or order the senses, so games show the most common meaning first.
- [ ] **Phase 4: expand es in bulk (owner decision 2026-11-03).**
  - Spanish is richer than English and the es list must be **much larger than it is now**.
  - **Target: more than 50,000 lemmas**, toward the DLE's ~93k, so es ends up bigger than the cleaned
    en list.
  - **Bulk source: the es.wiktionary dump.**
    - Get it from `dumps.wikimedia.org/eswiktionary/`, latest `pages-articles`.
    - Write a reproducible importer `scripts/words/importWiktionary.ts`, wired as a yarn script, that:
      - streams the XML dump;
      - keeps the Spanish sections only (`{{lengua|es}}`);
      - extracts the lemma, the part of speech (map it onto the Phase 1 closed type list) and the
        numbered senses as plain text, with wiki markup and templates resolved or stripped;
      - drops entries with no usable sense;
      - writes the same entry shape as today.
    - Each new word passes the Phase 1 checks (junk, encoding, blocklists).
  - **Licence:** Wiktionary is **CC BY-SA**. Add the attribution and keep the licence:
    - a credits entry in the app (About/credits page or README) and in `ops/docs/commands.md`;
    - a `source` field per entry (`wiktionary` / `rae` / `mw` / `dictionaryapi`), so the origin is
      traceable;
    - a note on share-alike for the definition data.
  - **RAE stays the quality layer.** RAE entries win over Wiktionary entries for the same lemma.
    Phase 3's RAE re-crawl and later quota runs refine the most frequent words first.
  - Do the import in **batches by letter**, one commit per letter file, so diffs can be reviewed.
    The PR reports per letter: lemmas before → after, plus a 20-entry sample.
  - **Inflected forms** (plurals, feminine forms, conjugations) are **not** lemmas. Don't add them as
    words, unless a game needs them (check `isEligible` per game) and the job lists which games do.
  - Games must not get worse:
    - re-run the per-level counts;
    - frequency-rank the new words (`ops/scripts/frequency` or a licensed frequency list), so beginner
      levels keep common words and rare words go to advanced;
    - the per-level length limits still apply.
- [ ] **Phase 5: en quality.** Audit and clean the en list the same way. It is 5× larger than es, so
  most work is removal.
  - Drop archaic and obscure entries that don't fit a word game, using frequency as the guide.
    After Phases 4–5, es must be larger than en.
  - Keep British English as the README states. Merriam-Webster is American: flag spelling variants
    (colour/color) and decide one policy, written in `ops/docs/commands.md`.

## Done when (each phase)
- The data files are valid JSON with the same shape. `yarn test` and `yarn build` are green, and every
  game still loads words for every level and locale.
- The PR body carries before → after counts per category, samples of what was removed or changed,
  and the remaining backlog.
- The check script runs in one command and is documented in `ops/docs/commands.md`. A test runs it on
  a fixture, so junk can't come back.
