# JUE-0009: word data clean-up and expansion

Every game draws from the definition files `public/definitions/<locale>/<letter>_definitions.json`
(26 files per locale). Today:
- **es:** 9,010 words;
- **en:** 45,984 words.

The entry shape is `word → {definitions: [{number, type, type_extra?, definition, definition_extra?}]}`.

The data was built with the crawlers in `scripts/crawlers/`:
- RAE for es: 10 requests/min, 100/day, exits with code 2 when the quota runs out;
- dictionaryapi.dev and Merriam-Webster (needs `MW_API_KEY`) for en.

It also went through the word scripts in `scripts/words/`: transform, merge, check, clean,
sort-by-frequency and from-book. See `ops/docs/commands.md`.

Owner decision (2026-11-03): improve every word with its definitions, remove junk, and expand the
lists.

## Pending (one phase per PR, in order; each launch does the first unchecked phase)
- [ ] **Phase 1: audit and clean (es + en).** Write a check script in `scripts/words/` (or extend
  `words:check`) that lists and fixes these:
  - **Junk words:** proper nouns, abbreviations, foreign words in the es list, words with digits or
    symbols, broken encoding (mojibake, NFD vs NFC), duplicates that differ only by case or accents,
    offensive words (keep the blocklists in `scripts/words/` as the source and extend them).
  - **Junk definitions:** empty ones, truncated ones, leftover HTML or markup, crawler noise
    ("Ver …", cross-references with no text), and definitions that only say "plural of X" or
    "forma de X" with no meaning.
  - **Wrong part of speech** or `type` missing. Normalise the `type` values across files: decide one
    closed list per locale and map variants onto it.
  - Fix what is fixable automatically. Delete what is junk. Write the counts per category (before →
    after) in the PR, plus a sample of 20 removed words per category so the owner can review them.
  - **No game may break:** every game's level must keep enough eligible words. Re-run the per-level
    counts (reuse JUE-0008's script if it exists).
- [ ] **Phase 2: definition quality (es).**
  - For words with weak definitions, re-crawl RAE: those with only a "forma de" reference, a missing
    type, or more than 6 senses that overwhelm the definition games.
  - Respect the quota: at most 100 per run. Keep a progress file so later runs continue where this
    one stopped, and make the crawler resume.
  - Add a `primary` sense flag, or order the senses, so games show the most common meaning first.
- [ ] **Phase 3: expand es.**
  - Grow the es list toward common vocabulary: frequency-ranked lemmas from `ops/scripts/frequency`
    or a frequency list with a licence, plus `words:from-book` sources the owner has.
  - Crawl the missing words from RAE in quota-sized batches, with the same resumable progress file.
  - Target: report how many common lemmas are missing, and set the target per run as at most 100 new
    words.
  - Each new word passes the Phase 1 checks before it is added.
- [ ] **Phase 4: en quality.** Audit and clean the en list the same way. It is 5× larger than es, so
  most work is removal.
  - Drop archaic and obscure entries that don't fit a word game, using frequency as the guide.
  - Keep British English as the README states. Merriam-Webster is American: flag spelling variants
    (colour/color) and decide one policy, written in `ops/docs/commands.md`.

## Done when (each phase)
- The data files are valid JSON with the same shape. `yarn test` and `yarn build` are green, and every
  game still loads words for every level and locale.
- The PR body carries before → after counts per category, samples of what was removed or changed,
  and the remaining backlog.
- The check script runs in one command and is documented in `ops/docs/commands.md`. A test runs it on
  a fixture, so junk can't come back.

## Notes
- Default branch `main`. Use yarn, never npm. Don't commit `next-env.d.ts`.
- **Run after JUE-0008** (spike) if its report exists: use its findings on the definitions and its
  word counts per level as the baseline.
- API keys come from the environment (`MW_API_KEY`). Never commit them. If one is missing, that
  crawler step is a blocker for the run, and the rest continues.
- Never change the data schema without updating every reader in `services/WordsService.ts` and the
  games, plus their tests.
- Large data diffs: commit per letter file or per category, so the PR can be reviewed.
