# JUE-0021 — Mobile: play every game on a phone, fix it, and install the site

Owner (2026-11-10): play all the games on mobile and fix the ones that look wrong or are not playable; add a
button that puts the site on the phone's home screen so it opens like an app.

Today `public/site.webmanifest` exists (name, one 192 px icon, `display: standalone`, white theme) and
`app/layout.tsx` links it, but there is no 512 px icon, no `start_url` / `id` / `scope`, no English variant, and
nothing in the page offers the install.

## Pending
- [ ] **Play every game on a phone, es and en**, by touch only, at 360, 375 and 390 px wide (headless Chromium
      with device emulation: touch, devicePixelRatio 3, portrait; plus landscape for the timed games). For each
      of the 11 games: rules visible, a full round played to the end, play again. Record per game what is wrong:
      horizontal page scroll, controls cut off or under the keyboard, tap targets under 44 px, text that does
      not fit, the on-screen keyboard hiding the input, a timer that runs out while the keyboard opens.
- [ ] **Fix every finding** at the narrowest layer (the game's SCSS or UI), with a before/after screenshot per
      game in `$JON_ASSETS_DIR/jue-0021/`. Coordinate with JUE-0016 (crossword grid and wordBuilder at 375 px):
      do here only what JUE-0016 does not already cover, and say which in the PR.
- [ ] **Installable site:**
  - complete the manifest: 192 and 512 px icons (plus a maskable one), `start_url: "/"`, `id`, `scope: "/"`,
    `theme_color` / `background_color` matching the site, `lang: "es"`; the en pages get an English
    `name`/`description` (a second manifest linked from the en layout, or one neutral manifest — say which);
  - meet the current Chrome installability criteria (check them when implementing; do not add a service worker
    unless they require it, and if one is added it must not cache the word data, which IndexedDB already holds);
  - an **"Instalar la app" / "Install the app" button** (header or footer, both locales): on Android/Chrome it
    shows the browser's install prompt (`beforeinstallprompt`); on iOS Safari, which has no prompt, it shows the
    short steps (Share → Add to Home Screen); hidden when already installed (`display-mode: standalone`) or when
    the browser can't install.
- [ ] Open the installed site in standalone mode (emulated) and play one game: no browser UI needed to navigate
      back home.

## Done when
- A table in the PR with every game × width (es and en): playable yes/no before and after, and what changed.
- No game has horizontal page scroll or a control out of reach at 360 px, checked by a script in the PR that
  measures `document.scrollingElement.scrollWidth` and the tap targets on every game page.
- Lighthouse (or Chrome's installability check) reports the site installable; the install button opens the
  prompt on emulated Android Chrome and the steps on emulated iOS Safari, and is hidden in standalone mode.
- UI tests for the install button (prompt available → shows and calls it; iOS → steps; standalone → hidden).
- `yarn test`, `yarn lint`, `yarn build` pass.
