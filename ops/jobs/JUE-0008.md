# JUE-0008 — spike: review of all the games

A **spike** (see `~/.claude/WORKFLOW-spike.md`). Review every game in depth and write the report to
`ops/jobs/spikes/JUE-0008.md`. It must cover playability, how many words each level really gets, bugs
and problems of that kind. The report ends with **proposed jobs**. The owner will open real jobs
from them. This spike changes nothing in the product and creates no job files.

Games in `games/`:
- `accentFixer`
- `crossWordPuzzle`
- `definitionMaster`
- `letterMatcher`
- `spellTower`
- `syllableSplitter`
- `wordBuilder`
- `wordFinder`
- `wordsRain`

Also cover the daily word (`WORDS_DAILY`) and any other game pages under `pages/` that aren't in
`games/`.

## Pending (questions the report must answer, for every game and for each locale es/en where the game has it)
- [ ] **Words per level.** How many eligible words each level (beginner, intermediate, advanced)
  really has after every filter. Count, don't estimate.
  - Filters: `WORD_GROUP_FETCH_CONFIG` min/max length, the game's own `isEligible`, the definition
    data `public/definitions/<locale>/*_definitions.json`, the blocklists, dedupe.
  - Report the distribution by length and by letter.
  - Report how many sessions it takes before words repeat, and whether a level runs dry or falls back
    to another level's words.
  - Write a measurement script in `ops/jobs/spikes/JUE-0008/` and run it on the real data.
- [ ] **Difficulty curve.** Does each level actually get harder? Compare word length, word frequency
  (the repo has `ops/scripts/frequency`), accents/ñ/hiatus and timer pressure across levels. Flag any
  level where beginner and advanced overlap or a jump is too big.
- [ ] **Playability.** Play every game in a headless browser (headless-browser skill: build with
  `yarn build`, serve `out/`, kill the server after). Check:
  - the rules are clear on first open;
  - the controls on mobile (375px) and desktop;
  - feedback on right and wrong answers that is not by colour alone;
  - timer fairness;
  - the session length;
  - what happens at the end (results, retry);
  - score clarity;
  - anything frustrating or confusing.
  Take screenshots to `$JON_ASSETS_DIR/jue-0008/<game>/`.
- [ ] **Errors.**
  - Look for wrong answers accepted or right ones rejected: accents, uppercase, ñ, the syllable rules
    (JUE-0004), definitions that don't match the word.
  - Look for crashes and JS console errors, broken states (refresh mid-game, empty pool, failed load),
    layout overflow (long words, as found in JUE-0004) and i18n gaps (missing keys, mixed languages).
  - Sample the definitions data for quality: empty, truncated or HTML junk, and wrong part of speech.
- [ ] **Consistency across games.** Shared patterns from `ops/docs/game-conventions.md` (word
  services, storage keys, levels, results screen). Flag where a game deviates for no reason. Cover
  accessibility basics: focus order, aria-live for results, labels.
- [ ] **Tests.** What each game's tests cover against what the findings show is untested.
- [ ] **Report** `ops/jobs/spikes/JUE-0008.md` in Spanish, following `WORKFLOW-spike.md`:
  - a per-game section with findings and evidence;
  - a summary table of words per level per game;
  - the cross-game issues;
  - the **proposed jobs**, ranked by impact. Each one gets title, goal, scope, done criteria, effort and
    workflow.

## Done when
- The report exists with every question above answered for every game, each finding backed by
  evidence (file:line, script output or screenshot).
- The measurement scripts are in `ops/jobs/spikes/JUE-0008/` and run with one command, documented in
  the report.
- No change outside `ops/jobs/spikes/`, apart from the close-out in `memory.md`.
